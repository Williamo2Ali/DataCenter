# إعادة هيكلة المستودعات (حاوية مشفرة لكل مستودع)

> القرار: "مستودع" اسم أليف للحاوية — كل مستودع = ملف مشفر واحد. ما عداها مرفوض.
> القاعدة: لا بايت نصي مفهوم خارج التشفير إلا ما في القائمة البيضاء أدناه — ويُتحقق آلياً.
> قاعدة عمل: لا بدائل تُقترَح بعد التجميد إلا بطلب صريح — هذه النسخة هي المرجع الوحيد.

## 1. الهيكلية

```
Folder Repository/
|__ repo.vault      (الترويسة 4KB أولاً ثم بايتات SQLite المشفرة بكلمة المرور)
|__ files/
    |__ file1.enc
    |__ file2.enc
```

* لا عناصر أخرى ولا استثناءات. البديل المرفوض نهائياً: إدخال الوسائط داخل الملف (فراغات + دمج دوري).
* الصيغة: `MAGIC | version | salt | iv | AES-256-GCM` بإعادة استخدام **دالة** التشفير في `vault.rs` (`encrypt_envelope`) المجرّبة، ببصمة سحرية خاصة بالمستودعات.
* توضيح ملزم (منعاً للخلط): الدالة تُعاد استخدامها لتشفير ملفات الوسائط — ولا يوجد أي تغليف إضافي حول القاعدة نفسها.
* كلمة المستودع إجبارية دائماً (مشتق PBKDF2 بـ 120k) — لا مستودع بلا كلمة. نفس الكلمة تفتح القاعدة والوسائط معاً (salt مستقل لكل ملف) — لا كلمات جديدة على المستخدم.

## 2. الترويسة (RepoHeader) — المصدر الوحيد

* كتلة نصية ثابتة 4KB في أول ملف `.vault` (سحرية + إصدار + طول + JSON مبطّن) — تحديث موضعي للكيلوبايتات الأولى فقط، بلا إزاحة لبقية الملف.
* القائمة البيضاء المغلقة: `{v, id, name, peopleCount, filesCount}` + محجوزات فارغة `{info, note, tag, caption}`. ما عداها يُرفَض عند الكتابة + اختبار يفحص كل ترويسة منتَجة.
* سقف 255 حرفاً (عدّ الحروف حفاظاً على العربية) لأي قيمة نصية، يُفرَض في دالة كتابة واحدة + اختبار حدودي. الإصدار يحكم التوسع (تجاهل المجهول + افتراضيات للناقص). أي حقل جديد يجب أن يجتاز سؤال "وصول أم سر؟".
* قراءة وعرض حصراً: القائمة الرئيسية، الأسماء، العدادات، استهداف الفتح — للمقفلة وغير المقفلة. ممنوع أي مصدر حقيقة آخر لأي معلومة تغطيها.
* مزامنة إلزامية مع **كل كتابة ناجحة** (لا عند الإغلاق فقط). عند الفتح تُعاد الحسابات من الداخل — تطابق صمت، واختلاف تجاهلٌ للداخل مع تحذير صريح.
* مبدأ "الأسماء وصول لا أسرار" (نموذج التهديد: متصفح ملفات عابر لتطبيق محلي): أسماء المستودعات والأشخاص والعدادات تبقى نصية لخدمة القائمة والبحث — كلمة "تسريب" لا تنطبق عليها. المشفر فعلاً: كل المحتوى.

## 3. القاعدة الحية (ذاكرة — بلا SQLCipher)

* أُسقط SQLCipher نهائياً: لا اعتماديات أصلية جديدة (كلفته بناء NDK وحجم ثنائي بلا عائد لهذا الحجم).
* الدورة: الفتح بكلمة المرور → فك الحمولة **للذاكرة فقط** (`:memory:` — لا ملف مؤقت على القرص أبداً) → عمل SQL طبيعي → مع كل عملية معدِّلة تُسلسَل القاعدة وتُشفَّر وتُكتَب في الحاوية + تُحدَّث الترويسة (كيلوبايتات بأجزاء من الثانية).
* الإغلاق/العطل/زر Home: المحفوظ على القرص مشفراً دائماً — لا فقدان إلا مسودة نموذج غير مرسلة (كاليوم) + لقطة تشفير تلقائية عند `onPause` حزاماً إضافياً.
* المرفوض هنا: الملف المؤقت النصي (نافذة مكشوفة + انشطار الحقيقة عند القتل) — رفض نهائي.

## 4. الوسائط المستقلة

* الفيديو والصور والصوت والمستندات: تشفير مرة واحدة عند الإضافة (`fileN.enc` بأسماء معتمة في `files/`)، لا تُمس مع حفظ النصوص، حذف ملف = حذف ملفه وانتهى.
* القراءة: فك تدفقي/كامل للذاكرة لحظة العرض فقط. إعادة تسمية `file.enc` لامتداد وهمي لا تُنتج ملفاً صالحاً (اختبار قبول).
* المشغلات لا تعرف التشفير: طبقة التطبيق تفك للذاكرة وتسلّم العارض رابطاً عادياً — العارضات الحالية (PDF/صور/فيديو/نصوص) بلا أي تعديل، وبنفس عتبات الأحجام اليوم (25/100/200MB — ما فوقها توجيه للمشاركة).

## 5. المشاركة

* مشاركة ملف واحد لتطبيق خارجي (زر صفحة المعاينة الحالي): فك نسخة لكاش خاص + تسليم عبر `FileProvider` + مسح مؤكد + مسح شامل للكاش عند كل إقلاع + استبعاد الكاش من النسخ الاحتياطي.
* مشاركة المستودع كاملاً: نسخ ملف الحاوية ومجلد `files/` لأي مجلد أو USB (الملف الواحد هو التصدير) — الزر في شاشة الاستقبال (`PanelWelcomeRepo`) فقط: زر بمنطقة الأزرار المشتركة بهيدر الموبايل (`CommonButtonsArea`)، بلا زر في كارد الرئيسية.

## 6. الأنظمة القائمة

* الفهرس العام (`people_index.json` + أمر `search_people_index` + صفحة `PageGlobalSearch`): **يُحافَظ عليه كما هو بلا أي تغيير** — يعمل ومُثبَت ميدانياً على الهاتف. ينسخ الأسماء لحظة الكتابة والمستودع مفتوح، فيُبحث في المقفلة دون فتحها.
* Drive/OAuth: مطوية نهائياً — لا مزامنة سحابية بأي شكل.
* الواجهات: نفس الشاشات والسلوك — تُعاد توصيلها فوق الملف الواحد.

## 7. التقسيم الإجباري

* الطبقة الجديدة تولد مقسمة: `repos/` (`mod.rs` + `peoples.rs` + `passports.rs` + `documents.rs` + `accounts.rs` + `contacts.rs` + `custom_tabs.rs` + `columns.rs` + `common.rs`). العمليات العابرة للجداول (حذف شخص = 6 جداول في معاملة) بملكية واحدة معلنة. لا يُعاد تنظيم الكود الميت قبل الهجرة.
* الحالة التنفيذية (2026-10-11): تم تقسيم ملف `repos.rs` (كان أكثر من 5200 سطر) على عمليتي تقسيم إلى جذر صغير `src-tauri\src\repos.rs` (الأنواع والفهرس وأوامر القائمة — يقوم مقام `mod.rs`) + 14 ملفاً في `src-tauri\src\repos` (`accounts.rs` + `columns.rs` + `common.rs` + `contacts.rs` + `custom_tabs.rs` + `documents.rs` + `lock.rs` + `open.rs` + `passport.rs` + `people.rs` + `schema.rs` + `tabs.rs` + `tests.rs` + `transfer.rs`). الفروق الاسمية عن القائمة الأصلية (`people.rs`/`passport.rs` بالمفرد، والملفات `lock.rs`/`open.rs`/`schema.rs`/`tabs.rs`/`transfer.rs`/`tests.rs`) ناتجة عن عمليتي التقسيم وموثقة هنا بلا تغيير بنيوي جديد. تجربة المستخدم على الهاتف في وضع Debug عبر `android-dev-usb.ps1`: التطبيق يعمل.

## 8. البيانات والحوكمة

* البيانات الحالية وهمية — بلا ترحيل، حاويات نظيفة.

## 9. بوابات القبول (معتمدة كاملة بلا شطب)

1. هيكلية حرفية بلا زوائد؛ الترويسة 4KB صالحة بمفاتيح بيضاء فقط.
2. فحص بايتات القرص الخام: أي نص مفهوم خارج الترويسة = فشل.
3. كلمة خاطئة تُرفَض + عبث بايت واحد يُكتشَف ويُرفَض.
4. دورة كاملة سليمة: إنشاء/فتح/كتابة/إغلاق/نقل لجهاز آخر/فتح بكلمة واحدة.
5. فقدان كلمة المرور = فقدان البيانات نهائياً (موثق بلا باب خلفي).
6. الترويسة محدثة مع كل كتابة + العبث اليدوي فيها = تحذير والداخل معتمد.
7. مراجعة بشرية بملفات حقيقية على الهاتف والويندوز.
