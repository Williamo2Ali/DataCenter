# DataCenter — مركز البيانات

تطبيق إدارة مستودعات البيانات العائلية (جوازات، سجل مدني، هويات وطنية، شهادات دراسة، ملفات، حسابات، جهات اتصال) بواجهة عربية/إنجليزية، يعمل على الديسكتوب (Windows/Linux عبر Tauri) والأندرويد من نفس الكود.

## المزايا

- **مستودعات متعددة**: إنشاء/فتح/قفل بكلمة مرور، تصدير/استيراد قاعدة كل مستودع (`data.db`) من كارده في الرئيسية، نسخ احتياطي واستعادة (`.dcbackup`) — أيقونتا التصدير/الاستيراد معكوستان مقصود، ورسائل النجاح/الخطأ تُعرض عبر `react-theme-toast`.
- **تبويبات فيزيائية**: 7 أساسية ثابتة البنية + مخصصة ينشئها المستخدم (جدول حقيقي لكل تبويب) — أسماء عربية وإنجليزية، ترتيب، إخفاء، وحذف ناعم مع استعادة فارغة.
- **لوحة تبويبات جانبية**: وضع موسّع ووضع شريط أيقونات (Rail) مطوي، دائم الظهور مع المستودع.
- **هيدر الموبايل**: زر اللوحة (boxarea1) + ترس الحساب (boxarea2) مع مستودع مفتوح، ثم المناطق السياقية.
- **موبايل**: هيدر حسب المنصة (أندرويد → موبايل، وغيره → ديسكتوب — لا حجم الشاشة)، شريط تنقل سفلي (5 أزرار)، درج تبويبات عائم، دعم النوتش وأزرار النظام، وزر Back بأسلوب المتصفح.
- **وضع نقل البيانات**: نافذة ضيقة فوق النوافذ لنسخ النصوص بسرعة (ديسكتوب فقط).
- **تخصيص**: لغة، مظهر فاتح/داكن، خط، حجم عرض (زوم 80–120%) — تُحفَظ في `settings.json` بجذر AppData (المصدر الوحيد، لا localStorage).

## نظام اللوحة (Panel)

- `PanelEmpty`: غلاف تخطيطي فقط. `open=false` = خارج DOM. `collapsed` = شريط 60px. `overlay` = طبقة عائمة فوق المحتوى (درج الهواتف) مع دخول/خروج متحرك.
- `PanelRepoTabsViewer` (≥640px): بحث + قائمة + تذييل (`state` للطي/التوسيع و`closerepo`). الشريط المطوي بأيقونات + شارة X حمراء للإغلاق + زرّي تمرير بدل السكرول.
- `PanelRepoTabsViewerMob` (<640px): header (إغلاق + بحث) / body (تمرير عمودي مخصص) / footer (إغلاق المستودع بحشوة `py-2.5` فقط — بلا `safe-area-inset` لأن الدرج محصور بين الهيدر والشريط السفلي وحشوة النظام ملك الشريط وحده) — مستقل تماماً عن نسخة الديسكتوب.
- عند فتح مستودع تبدأ اللوحة **مطوية** دائماً.
- هيدر الموبايل: صف واحد إجباري (`grid-flow-col` لا يلتف) — العنوان + مناطق الأزرار الأربع
  من اليسار (`panelToggle` = المنطقة 1 + 3 سياقية، أزرار `40px`)؛ المنطقة 1 Toggle للوحة
  (درج الهواتف أو طي اللوحة) بدل زر الشريط السفلي (مخفي مع مستودع مفتوح)؛
  تُزال كلها عند الإغلاق ويبقى بروفايل فقط.
- الشريط السفلي 5 أزرار (الأوسط home): وهميان + home + زر PagePrompt المستقبلي (معطّل، مرجعيته
  `plan/ai_prompt_extract_text.md`) + الحساب.
- زر الحساب بهيدر الموبايل مخفي (لا محذوف) عند فتح مستودع — تحل المنطقة المخصصة
  محله، والوصول للحساب يبقى عبر الشريط السفلي.
- اختيار الفرد على الهواتف عبر مودال بطاقات (الاسم + الصفة) — صف `member-tabs`
  مخفي تحت `640px`، واسم الفرد الحالي يظهر في الهيدر الموحد.
- هيدر التبويبات موحد (`RepoTabsHeaderControl` + أصناف `.rtc`): نصوص ellipsis بلا التفاف،
  وعدّاد الحقول بعرض زرّين وارتفاع زر واحد — لكل التبويبات وعلى كل الشاشات.

## حالات التبويبات (App.tsx)

`closedTabIds` (تُحفظ per-repo في localStorage) + `activeSection` (`__empty__` = الكل مغلق → صفحة استقبال `PanelWelcomeRepo`: بطاقة المستودع + إحصاءاته + زر فتح قائمة التبويبات). مستودع جديد بلا حالة محفوظة = كل التبويبات مغلقة. فتح أي تبويب ينقل لصفحة المستودع.

## المستودع الجديد (Rust: `seed_repo_structure` + `merge_factory_defaults`)

- البنية (التبويبات الأساسية السبعة) دائماً + سجل فارغ لكل اسم عضو يُدخل.
- عدد الأعضاء صفر = شخص تجريبي واحد (UUID حقيقي) — يُحذف يدوياً.
- كل شخص (بما فيه التجريبي) يُزرَع بصف 1-1 فارغ في الجداول الأربع ليعرف المستخدم ماذا يملأ.
- مودال الإنشاء يعرض خيار المحتوى: **مع القالب** (افتراضي) أو **فارغ** (`withDefaults` —
  تبويبات وأشخاص بلا صفوف فيزيائية، لمن سيملأ بالاستيراد الذكي) — قابل للعكس عبر الاستعادة.

## عزل المستودعات والبنية الفيزيائية

- كل مستودع خزنة مستقلة: جداوله في `sqlite` خاصته فقط — لا مزامنة عامة.
- العام الوحيد = ثوابت `TABS` في `repos.rs`: تُزرَع عند الإنشاء وتُدمَج بزر «استعادة الافتراضي»
  (الناقص فقط — لا يمس المخصص ولا القيم، ولا يحيي المحذوف ناعماً). `tabs.json` متقاعَد.
- **الأشخاص** (`peoples` — بدل `records` المحذوف): الاسم والصفة إجباريان باللغتين، والمعرف UUID
  معتم لا يُشتق من الأسماء. حذف الشخص يحذف صفوفه 1-1 وحساباته + يفك ربط ملفاته وجهاته (`NULL` فتصبح مشتركة).
- **التبويبات الأساسية السبعة** بنيتها ثابتة: حذف التبويب **ناعم** (`delete_core_tab` — مسح البيانات
  كاملة + وسم `is_deleted`، وللملفات: الكتل من القرص أيضاً) + استعادة فارغة (`restore_core_tab`)؛
  والمخصص إنشاؤه `CREATE TABLE` لحظياً وحذفه إسقاط فيزيائي. المحذوف مستثنى من كل العروض والعدادات.
- **الأعمدة الإضافية**: أي جدول (أساسي 1-1 أو مخصص) تُضاف له أعمدة من مدير الأعمدة
  (`ALTER TABLE` حقيقي + سجل `custom_columns`) — تُعرض وتُحرَّر وتُستورَد مع الأساسية.
  (مخطط معتمد للتنفيذ: `plan/New/columnSoftDelete.md` — إخفاء ماسح للأعمدة الأساسية مع مسح بياناتها).
- الإخفاء (`is_hidden` على الجداول): المخفي مستثنى من كل العروض والعدّادات، ويُدار (شارة + زر عين) من صفحة الجداول.
- اسم عرض المستودع يُغيَّر من كارد الرئيسية في أي وقت (`rename_repo`) — المعرف الفيزيائي ثابت.
- **تصدير/استيراد قاعدة المستودع من كارده** في الرئيسية (بوابة القفل + دمج WAL + نسخة `data.db.bak` +
  تنظيف بقايا WAL) — `data.db` فقط دون `files/` (الشاملة `.dcbackup`).
- ثنائية اللغة إلزامية (`label/label_en` + `value/value_en` للأعمدة الفيزيائية) + لغة عرض
  (`fieldLang`: عربي/إنكليزي فقط — لغة واحدة في الخانة، بلا خلط) وزر تبديل سريع في العارض.
- التحرير مدمج: **مفرد** (قلم كل صف — لغتاه معاً) و**شامل** (`PhysicalForm` بكل الأعمدة) —
  مع نسخ كل قيمة وتحقق (ISO والسنة ومفاتيح القوائم).
- أي حساب على أي موقع = `accounts` (CRUD كامل لكل فرد). جهات الاتصال جدول حقيقي (مالك/مشترك + CRUD).
  الصور بلا تبويب مستقل (`documents.kind='image'` يُغني عنه — تبويب `images` محذوف نهائياً).

## الإشعارات (Toasts) — `react-theme-toast`

الإشعارات لم تعد كوداً داخلياً: حُذف مجلد `src/components/NotificationToast/` نهائياً وحلّت محلّه
**مكتبة خارجية** اسمها `react-theme-toast` (v1.0.0)، مبنية على متغيّرات CSS.

### التركيب

المكتبة تُثبَّت من ملف tarball محلي (ليست منشورة على npm):

```powershell
npm install "E:\Programes\React Projects\react-theme-toast-v1.0.0\react-theme-toast-1.0.0.tgz"
```

> npm يسجّل المسار **نسبياً** في `package.json` كـ
> `"react-theme-toast": "file:../react-theme-toast-v1.0.0/react-theme-toast-1.0.0.tgz"`،
> أي أن مجلد `react-theme-toast-v1.0.0` يجب أن يكون **شقيقاً لمجلد المشروع**. إن نُقل المشروع،
> فنسخ المجلد معه أو ثبّت المسار الكامل.

### الاستخدام

المزوّد مركّب في `App.tsx` (داخل `LanguageProvider` مباشرةً):

```tsx
import { ToastProvider, createToastTheme } from 'react-theme-toast'

<ToastProvider mode={settings.theme} position={toastPosition} defaultDuration={4000} theme={toastTheme}>
  {children}
</ToastProvider>
```

- **الموضع متجاوب** (`App.tsx`): أعلى-المنتصف حتى الشاشات المتوسطة، والزاوية
  العليا لبداية السطر (`top-start` = اليمين في RTL) من `1024px` فأعلى — عبر
  `matchMedia` مع تحديث حي عند تدوير الهاتف أو تغيير النافذة.

- **الاستدعاء من أي مكوّن**:

  ```tsx
  import { useToast } from 'react-theme-toast'

  const toast = useToast()
  toast.success('تم الحفظ')                 // يعيد معرّف الإشعار (string)
  toast.error('تعذّر الحفظ', 'سبب الخطأ')   // الرسالة الثانية اختيارية
  toast.info('ملاحظة', 'نص', 6000)          // الأنواع: success / error / info
  toast.dismiss(id)
  toast.dismissAll()
  ```

  يجب استدعاء `useToast()` **داخل** شجرة `ToastProvider` (أي داخل التطبيق نفسه).

- **لا حاجة لاستيراد CSS**: تحقن المكتبة أنماطها (`.rt-viewport` / `.rt-toast`) في `document.head`
  عند تركيب `ToastProvider`. وتصدّر `BASE_CSS` و`ensureToastStyles()` لمن يحتاجهما يدوياً فقط.

- **الوضع الليلي**: `mode={settings.theme}` يربط المكتبة بإعداد التطبيق (`'light' | 'dark'`)
  فتتبع تبديل المظهر دون كود إضافي.

- **ربط الألوان بالثيم**: `toastTheme` في `App.tsx` تمرّر **متغيّرات CSS لا ألواناً ثابتة**
  (`var(--paper)`, `var(--ink)`, `var(--muted)`, `var(--line)`, `var(--green)`, `var(--orange)`)
  — وهي القاعدة نفسها المتّبعة في بقية المكوّنات، فتتبع الفاتح والداكن بلا `darkTheme` منفصل.

- `NotificationProvider` و`useNotifier` اسمان بديلان تصدّرهما المكتبة توافقاً مع الكود القديم؛
  الاسم المعتمد في التطبيق `ToastProvider` و`useToast`.

- **في التطبيق**: نجاح/فشل تصدير واستيراد قاعدة المستودع (`PageHome.doExport/doImport`)
  وصفحتا الجداول والحقول وصفحة الحسابات (`PageTableAccounts`: النسخ وفتح الرابط)
  تُعرض عبر `toast.success`/`toast.error` — لا رسائل صفحة داخلية.

## مكوّن التلميح المخصص (Tooltip) — إلزامي لكل المكونات

- يُستخدم حصرياً `src\components\Tooltip.tsx` لعرض التلميح على أزرار الأيقونات
  وكل عنصر يحتاج شرحاً مرئياً. يُمنع `title` أو مكتبات خارجية.
- `Tooltip` يرسم عبر `createPortal` فلا يقصّه `overflow-hidden` في الهيدر/اللوحات
  ولا يحجب المودالات، ويُقلب تلقائياً عند ضيق المساحة.
- الأزرار الأيقونية فقط في كافة الصفحات (`AppHeader*`, `AppMobileBottomNavBar`,
  `PanelRepoTabsViewer*`, `FileManager`, `DocumentLibrary`, `PageHome`, `PagePeoples`,
  `PageRepoViewer`, `PagePromptView`, `accounts/*`, `modals/*`, `vault/*`) مغلفة بـ `<Tooltip>`.

## مكتبة المكوّنات المشتركة (تُستخدم الآن)

خمسة مجلدات في `src/components` كانت **منسوخة من مشاريع أخرى** ومعطّلة كلياً داخل `DataCenter`:
كل مكوّن فيها كان يستورد وحدة غير موجودة في هذا المشروع (zustand, `@/lib/dates`, `@/stores/*`,
`ModalPeriod`, `@mui/x-date-pickers`, clsx…) ويستخدم كلاسز ثيم من مشروع آخر (`bg-card`,
`border-border`, `text-foreground`, `primary-600`…) لا وجود لها هنا. النتيجة: المجلدات الخمسة
كانت **مستبعدة من `tsconfig.app.json`** وكوداً ميّتاً لا يُستدعى، وثلاثة منها لا يمكن أن تُبنى أصلاً.

### ما الذي قُام به

| المجلد | فكّ الاعتماديات | الثيم |
|---|---|---|
| `Calendar/` | `settingsStore`/`lib/dates` ← خيارات `monthStyle`/`dateFormat`؛ `ModalPeriod` ← نافذة فترة مبنية داخل `DatePeriod` | ✅ |
| `ClockAlarm/` | حُذف `CustomTimePicker` (كان يحتاج MUI)؛ `TimeSelect` و`AnalogTimePicker` بلا استيراد | ✅ |
| `Colors/` | `@/components/ui` و`@/lib/utils` ← عناصر مباشرة + `cn` محلية | ✅ |
| `Custom/` | `@/components/ui`, `@/lib/utils`, `clsx`, `@/lib/formatters`, `@/services/*` ← كلها محلية؛ `buildGroupedLedgerRows` حُذف (يحتاج نظام محاسبة غير موجود) وبقي الجدول كاملاً | ✅ |
| `Groups/` | `clsx` ← دالة `cx` محلية | ✅ |

- **الاعتماديات**: صارت كل ملف مكتفياً بذاته — لا استيراد من مجلد خارجه إلا `react` و`lucide-react`.
- **الثيم**: كل لون صار من متغيّرات `index.css` (`--paper`, `--ink`, `--line`, `--green`, `--muted`)،
  فتبع الوضع الفاتح والداكن تلقائياً بلا سطر CSS واحد جديد. اللونان الأحمر والبرتقالي
  (خطر/تنبيه) استُبدلا بـ `#c8443c` و`var(--orange)` حتى يتطابقا مع باقي التطبيق.
- **البناء**: المجلدات الخمسة عادت إلى `tsconfig.app.json`؛ الاستبعاد único الباقي `src/lib/utils.ts`
  (نسخة `cn` يتيمة لا يستوردها شيء). حُذف `src/components/ui` نهائياً (13 ملفاً ميتاً، ولا شيء كان
  يستورده).

**القواعد التي تحكم كل من يلمس هذه المكوّنات** (لكل مهمة قادمة، آلياً كان أم بشرياً):

1. **لا تنسخ مكوّناً من مشروع آخر إلى هنا.** إن وجدت مكوّناً هناك، انقله بهذه القواعد نفسها:
   فكّ كل استيراد غريب، أوجد البديل داخل المجلد، ثم وحّد ألوانه على متغيّرات الثيم. إسقاط المكوّن
   داخل `tsconfig.app.json` ليس حلاً — هو ما أخفى هذه المشكلة خمس جلسات كاملة.
2. **ممنوع منعاً صريحاً**: `clsx`, `zustand`, `@mui/*`, `dayjs`, `tailwind-merge`, `@/stores/*`.
   لا شيء منها مثبّت في `package.json`. للدمج الأصناف استخدم دالة `cx` المحلية الموجودة في الملف
   نفسه.
3. **الألوان من الثيم فقط**: لا قيمة لونية ثابتة في JSX. إن احتجت تدرّجاً أخضر استخدم
   `color-mix(in srgb, var(--green) 10%, var(--paper))` كما في الملفات الحالية.
4. **انتبه لقاعدة عامة**: `index.css` فيه `button { font-size: var(--app-button-font-size) !important }`
   وأيقونات lucide داخل الأزرار تُقاس بـ `!important` أيضاً — أي أن `text-xs` وما شابه على عناصر
   `button` لا يسري. لهذا لا تترك حجم الخط في كلاسز Tailwind داخل الأزرار.
5. **لا تُعِد إنشاء ما هو موجود**: وإن احتجت تغييراً، عدّل المكوّن المشترك نفسه ليخدم الجميع.

المكتبة (18 ملف `.tsx`) جاهزة ومُختبَرة بصرياً في الوضعين الفاتح والداكن (بناء `tsc -b --force` +

## ملاحظات للمطور

- **قاعدة Mobile First**: الأساس دائماً شاشات الهواتف ثم التوسع للأكبر. أي مكوّن لا يصلح للشاشات الصغيرة تُنشأ له **نسخة موبايل مستقلة** (تكرار الكود مقبول) كما فُعل مع الهيدر (`AppHeaderMobile`) واللوحة الجانبية (`PanelRepoTabsViewerMob`) — حتى تبقى نسخة الديسكتوب معزولة عن أي تعديل موبايل.

- خطط التراجع المعلّمة: `planclosetab` (شارة X) و`planscrollrail` (أزرار التمرير).
- `tsconfig.app.json` لم يبقَ فيه إلا استبعاد واحد: `src/lib/utils.ts` (نسخة `cn` يتيمة لا يستوردها شيء بعد فكّ اعتماديات المكوّنات). الخمسة مجلدات المهاجرة (`Calendar`, `ClockAlarm`, `Colors`, `Custom`, `Groups`) كُشفت وأُعيدت إلى البناء، وحُذف `components/ui` — انظر «مكتبة المكوّنات المشتركة». **لا تُعِد إسقاط مكوّن في `tsconfig` لإخفاء أخطاء**؛ أصلح الاستيراد بدل ذلك. alias `@` معرّف في Vite وtsconfig معاً (`@/utils/helpers` لمولّد UUID).

- أمر `register_documents`: بوابة واحدة + معاملة واحدة + فتح واحد، والفاشل
  `{index, reason}` لا يحجب الناجح (مع رفض المكرر داخل الدفعة)؛ `saveStaged`
  نسخ متسلسل (سعة تراكمية) ثم تسجيل واحد، و`storeItem` انقسم لـ`copyItem`
  مشترك مع `saveOne`.
- ذاكرة جلسة `VERIFIED_PASSWORDS`: تطابق يتخطى PBKDF2 (تُعبَّأ عند الفتح/
  الكتابة، وتُمسَح عند أي `set_repo_password` أو `delete_repo` — وإلا قبلت
  قديمة)؛ طُبقت على البوابة والفتح والتحقق والحذف.
- تشخيص الفشل: سبب أول فشل + أول 3 أسماء في سطر التوست الثاني (كان يُبتلَع).

### مصغرات الفيديو (`FilePreviewPage.tsx` + `VideoThumbnail.tsx` + CSS)
- البياض سببه `<video preload="metadata">` بلا `poster` (لا يفك إطاراً) مع
  `asset://` بلا `Range` وفهرس `moov` في الذيل (وأحياناً HEVC) — بينما
  الرئيسي يعمل لأنه يحمّل الملف كاملاً (300MB+ مُجرّب).
- `VideoThumbnail.tsx`: لقطة أول إطار (fetch→Blob→seek→Canvas→JPEG 480px)
  بكسل تام (`IntersectionObserver`) + سقف 100MB (`sizeBytes` من الفهرس —
  بلا `stat` الميت على asset) + طابور تزامن 2 + مهلة 20s + تنظيف + Cache؛
  البديل أيقونة `Film` + شارة التشغيل `thumb-play` الدائمة.
- عتبة المباشر للفيديو `VIDEO_PREVIEW_BYTES=100MB` (تحت 100MB بلا زر «رغم
  ذلك»؛ 100–200MB تنبيه + زر؛ فوق 200MB تنبيه فقط) — `LARGE_FILE_BYTES`
  بقي 25MB للموجات.
- زر «عرض المزيد»: `.file-section-card > .add-field-btn` بملء الصف
  (`margin: 10px 0 0`) بدل فيض الهوامش الجانبية.

### التحقق
- `npx tsc --noEmit` و`cargo check` (exit 0) بعد كل موجة؛ JSON صالح؛ لقطات
  `adb` للشريط والأزرار؛ ملاحظة: جزء Rust يلزم إعادة بناء التطبيق (APK/EXE).

## سجل جلسة 2026-10-11 (البروفايل ملف + الإعدادات + المفضلة والفرز)

### ملف البروفايل `profile.json` (`profile.rs` جديد + `lib.rs` + الواجهة)
- الملف الشخصي خرج من `localStorage` إلى `AppData/profile.json` (كتابة ذرية
  + `.bak` للتلف + دمج متحقق) — بلا أي حقل سري. الصورة `dataURL` مقيدة
  بـ`jpeg/png/webp` وسقف `~300KB`، والمفاتيح الدخيلة (`passwordHash`)
  تُتجاهَل ولا تُكتَب.
- الواجهة: `readProfile/saveProfileFile` في الخدمة، و`loadProfileFile/
  saveProfileFileData` في المخزن مع هجرة لمرة واحدة من `idata-profile`
  (الحذف بعد نجاح الكتابة والتحقق فقط)؛ `localStorage` بديل تطوير فقط.
- تبويب البروفايل تحميل غير متزامن مع تعطيل الحفظ حتى الاكتمال، وعرضه
  مساوٍ لعرض بطاقة العام (حُذف انكماش `mx-2` تحت `760px`).
- كلمة مرور التطبيق **مؤجلة**: `TabSecurity` مخفي من الصفحة بتعليق لا حذف.

### تبويب عام في البروفايل + افتراضيات الهاتف
- اللغة والمظهر انتقلا من `settings.json` إلى `profile.json` (افتراضي
  عربية/فاتح) مع توريث قيم `settings.json` عند أول إنشاء؛ `App` يحمّل
  الملفين قبل العرض.
- افتراضيات العرض من قيم الهاتف المقروءة (`com.DataCenter.debug`):
  خط `17` وخط الأزرار `15` وخط `Cairo` — في `settings.rs` و`appSettings.ts`
  مع `defaultAppearance` للضبط.
- زر إعادة ضبط سياقي في هيدر الموبايل (عام/العرض فقط — الإغلاق أولاً ثم
  الضبط)، وأزرار الصفحات للديسكتوب فقط (`max-lg:hidden`) بلا تكرار؛ ضبط
  العام يعيد اللغة والمظهر والفرز معاً.
- التبويبات أُعيدت تسميتها «الجداول»، والجداول والحقول مخفية بلا مستودع
  مفتوح (مع إعادة العالق لحسابي).

### بوابات الكتابة للمقفول (`repos.rs` — بلا مساس بقواعد البيانات)

  فقط (بن نمط نافذة الحذف، بلا مفاتيح لغة جديدة).

### زر الرجوع في أندرويد (`App.tsx` + `PageMother.tsx`)
